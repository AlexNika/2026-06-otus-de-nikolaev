## Задание со звёздочкой

### Дополнительные вводные.
Через полгода появились новые требования:
- информация о пользователях стала поступать одновременно из CRM-системы и мобильного приложения;
- появилась новая семейная подписка, которая позволяет нескольким пользователям пользоваться одной подпиской.

### Вопрос 1. Потребуется ли создавать новые Hub, Link или Satellite?

**Да, потребуется.** Оба новых требования добавляют в модель новые объекты, но ни одно из них не заставляет переделывать старые.
1. **Семейная подписка.**
<br>Раньше тип подписки был просто атрибутом пользователя (лежал в Sat_User_Subscription). Но семейная подписка общая для нескольких пользователей – атрибутом это уже не выразить.
<br>Значит, подписка становится самостоятельной сущностью → появляется свой Hub, связь с пользователями → Link, а атрибуты подписки → Satellite при новом хабе:
   - Hub_Subscription – хранит бизнес-ключ подписки (SubscriptionID);
   - Link_Subscription_User – связывает одну подписку со многими пользователями (и один пользователь за время жизни может иметь разные подписки – это отношение "многие ко многим");
   - Sat_Subscription_Details – атрибуты подписки: тип (обычная / детская / семейная), даты начала и окончания и т.п. Тип подписки "переезжает" сюда из Sat_User_Subscription.<br>
   Платёж теперь нужно привязывать не только к пользователю, но и к подписке (платят-то за подписку) → добавляется Link_Payment_Subscription. Старый Link_Payment_User при этом не отменяется.
   <br>Плательщиком всё равно остаётся конкретный пользователь (владелец подписки), поэтому оба линка спокойно сосуществуют.
2. **Два источника данных о пользователях (CRM + мобильное приложение).**
<br>Хабы не меняются – бизнес-ключ пользователя один и тот же в обоих источниках.
<br>Но есть небольшая проблема: CRM и мобильное приложение могут присылать разные значения одних и тех же полей (например, разные телефоны).
<br>Если писать их в один сателлит, система будет считать, что пользователь "изменил" телефон, хотя на самом деле это просто два разных источника.
<br>Поэтому каждый источник хранится в своём сателлите.<br>Существующий Sat_User_Profile уже является сателлитом CRM (его RecordSource на это указывает),
<br>и нам достаточно добавить один новый – Sat_User_Profile_MobileApp с теми же профильными атрибутами, но со своим RecordSource.
<br>Обе версии данных хранятся параллельно, история не искажается.

**Итоговая таблица новых объектов:**

| Объект                    | Тип       | Ключи                                                             | Зачем нужен                                                                             |
|:--------------------------|:----------|:------------------------------------------------------------------|:----------------------------------------------------------------------------------------|
| Hub_Subscription          | Hub       | PK: Subscription_HK; BK: SubscriptionID                           | Подписка – самостоятельная сущность: одна подписка у многих пользователей               |
| Link_Subscription_User    | Link      | PK: Subscription_HK + User_HK; FK: Subscription_HK, User_HK       | Связывает подписку с её пользователями (M:N)                                            |
| Sat_Subscription_Details  | Satellite | PK: Subscription_HK + LoadDate; FK: Subscription_HK               | Атрибуты подписки: тип, даты начала/окончания. Сюда "переехал" тип подписки             |
| Link_Payment_Subscription | Link      | PK: Payment_HK + Subscription_HK; FK: Payment_HK, Subscription_HK | Платёж оплачивает подписку                                                              |
| Sat_User_Profile_App      | Satellite | PK: User_HK + LoadDate; FK: User_HK                               | Те же профильные атрибуты пользователя, но из мобильного приложения (свой RecordSource) |

* все новые таблицы, как и прежде, получают стандартные технические поля: LoadDate, RecordSource, а сателлиты – ещё и HashDiff.

### Вопрос 2. Какие таблицы останутся без изменений?

В Data Vault действует принцип "только добавляем, никогда не изменяем" (add-only). Поэтому все 12 существующих таблиц остаются структурно без изменений – никаких новых колонок или переделки ключей.
<br>Меняется только роль двух таблиц в загрузке:

| Таблица               | Тип       | Что с ней происходит                                                                                                                          |
|:----------------------|:----------|:----------------------------------------------------------------------------------------------------------------------------------------------|
| Hub_User              | Hub       | Без изменений: бизнес-ключ пользователя тот же, новые источники его не меняют                                                                 |
| Hub_Movie             | Hub       | Без изменений                                                                                                                                 |
| Hub_ViewSession       | Hub       | Без изменений                                                                                                                                 |
| Hub_Payment           | Hub       | Без изменений                                                                                                                                 |
| Link_Viewing_User     | Link      | Без изменений: просмотры не зависят ни от подписок, ни от источников                                                                          |
| Link_Viewing_Movie    | Link      | Без изменений                                                                                                                                 |
| Link_Payment_User     | Link      | Структура без изменений; продолжает наполняться: плательщик – конкретный пользователь (владелец подписки)                                     |
| Sat_User_Profile      | Satellite | Структура без изменений; теперь играет роль сателлита источника CRM, вся история сохраняется                                                  |
| Sat_User_Subscription | Satellite | Структура без изменений; для новых данных больше не наполняется (тип подписки "переехал" в Sat_Subscription_Details), но вся история остаётся |
| Sat_Movie_Info        | Satellite | Без изменений                                                                                                                                 |
| Sat_View_Details      | Satellite | Без изменений                                                                                                                                 |
| Sat_Payment_Detail    | Satellite | Без изменений                                                                                                                                 |
